# 2026-11-11 공식 화면과 제품 비교

기준 제품은 [fc66ed5d729e](https://github.com/knadalkim-a11y/team-agent-poc/commit/fc66ed5d729e7deeaa1fabc7d874cd816d1e006e)이다. [PR #135](https://github.com/knadalkim-a11y/team-agent-poc/pull/135)에서 최종 커밋 및 CI 결과를 확인한다. [피그마 원본](https://www.figma.com/design/XK2wTos6sEuxSHhIj7cqg6?node-id=1288-2)의 4개 공식 페이지를 사용했다. 70 작업실의 4판은 별도 검토안이다.

## 화면 확인 방법

PR의 최신 EES delivery 실행에서 `ees-work-browser-evidence-native-compose`를 내려받아 압축을 풀고 `ees-results/figma-review/index.html`을 연다. 8개 화면의 1104×1080 피그마 업무 영역과 1920×1080 제품 캡처 중 같은 영역을 나란히 표시한다. 원본 PNG와 DOM 실측도 함께 들어 있다. ‘상태별 전체 캡처’에는 A4-2·B4·480px 회차 상세·T07 등의 동작 결과가 있다. 파일이 없으면 해당 화면은 미확인이다.

변경 전까지 3개 열로 보려면 [기준 실행](https://github.com/knadalkim-a11y/team-agent-poc/actions/runs/42962981781)의 browser evidence를 풀어 ‘이전 빌드 캡처 폴더’에서 고른다. 이전 화면과 동일한 상태의 캡처가 없으면 그 차이를 표시한다. 파일 선택은 브라우저 안에서만 처리한다. 데이터 건수·예시 문구가 다른 두 이미지를 전체 픽셀 점수로 판정하지 않는다.

## 기존 제품 흐름을 채택한 두 화면의 피그마 보정안

- **B1** `835:323`의 가운데 프레임 `835:456`에 실제 제목·이름 검색·선택 범위의 절차 목록·각 행의 유형/단계 수/게시 표시를 배치한다. 새 워크플로우는 현재 목록의 아래에서 이름·목적을 받는다. 예시를 고른 뒤 질문 1~5를 거치는 화면은 별도 작성 방식의 검토안으로 분리한다. [기존 목록 결정](../docs/mockups/ees-work/TASK.md#operations31-authoring12-parity-20261030)
- **A8** `960:1177`는 왼쪽 작업 위치를 공유한다. 중앙에는 선택한 절차의 단계 개요를 배치한다. 공장이 필요하면 현재 위치를 안내하고, 명시적 시작 또는 기존 진행 건 열기로 이어진다. 조회·취소·화면 이동은 새 회차를 만들지 않는다. [기존 시작 계약](../docs/mockups/ees-work/TASK.md#operations-entry-legacy-removal-20261030)

## 판정의 근거

같은 통합 커밋의 실제 브라우저 PNG·치수·권한·저장·실행 테스트 결과를 함께 읽는다. 디자인 참고 이미지 8장은 실제 제품의 합격 캡처 수에 포함되지 않는다. 실행 당시 응답·권한과 사내 운영 데이터는 별도 환경이며, 사내 배포·사용자 확인은 이 PR의 범위에 포함되지 않는다.

## 첫 통합 실행의 회귀 확인

[0cc2ee2의 통합 실행](https://github.com/knadalkim-a11y/team-agent-poc/actions/runs/42978670712)에서 제품 빌드·패키징·실제 전체 제품 시험은 성공했다. Linux·Windows 서비스 시험은 T01의 예전 안내 문구 및 전체 class 문자열을 요구하는 Node 단언 4곳에서 실패했다. Native C66은 모든 일반 배지를 금지하여 실제 연결 버전 표시에서 실패했다. 목록 검색·범위 보존, 사용 불가 상태·시험 전 사용 금지는 계속 검증하며, 도구 버전은 조회 권한이 있을 때만 표시하고 권한 회수 후에는 숨기는 조건을 검증한다. 이 실행에서는 A4-2 상태 추적, 회차 왕복, B2/B4와 B6~B8의 합성 자료 시나리오가 통과했다. 최종 결과는 PR의 마지막 커밋을 기준으로 확인한다.
