# EES Work Runtime POC — 수락 기준과 검토 기록

이 파일은 [Contract·Runtime 설계](../docs/08-ees-work-contract-runtime.md)의 후속 구현·실환경 수락을 지속 관리한다. 현재 작업은 [STATUS](../docs/STATUS.md), 과거 패널/배포·운영 증거는 [기존 평가표](scenarios.md)에 보존한다. 새 세션별 평가 파일을 반복 생성하지 않는다.

<a id="acceptance"></a>

## 1. POC 수락 기준

아래는 **새 Runtime POC의 목표 시험**이다. 2026-09-16 문서 재검토에서 실행한 제품 시험이 아니며, 앞선 모의 점검·UI 시험의 PASS를 이 ID로 옮기지 않는다. 미실행은 실패를 뜻하지도 성공을 뜻하지도 않는다. 실제 사내 근거는 내부에 보관하고 Git에는 비밀값 없는 요약만 기록한다.

| ID | 확인할 사용자 흐름/경계 | 기대 결과 | 현재 판정 |
|---|---|---|---|
| RT-P01 | 직접 작성·AI 제안·복제로 같은 P/T/J 규격 작성 | 초안은 불완전 저장 가능, 필수 항목/순환/잘못된 참조는 게시 차단 | 미실행 |
| RT-P02 | 실제 승인된 읽기 J 실행 | 실제 호출과 대상·범위가 확인되고 구조화 결과가 저장됨. 모의 결과로 대체 불가 | 미실행 |
| RT-P03 | Criterion과 검증 체크의 연결 | 실행 성공만으로 PASS하지 않고 기준 ID별 관측·판정·근거 확인 | 미실행 |
| RT-P04 | HTTP 200의 잘못된 payload·대상 불일치·빈/부분 결과 | 실제 명세에 따라 FAIL/UNKNOWN 구분. 누락과 불완전 조회를 성공으로 처리하지 않음 | 미실행 |
| RT-P05 | 타임아웃·권한 철회·미연결·응답 누락 | 원인 보존, 판정 불가 시 UNKNOWN, 후속 의존 작업 완료 차단 | 미실행 |
| RT-P06 | 수동 확인·AI 초안·사람 검토 혼합 | 초안 생성과 승인 분리. 실제 사용자 확인 없이 AI가 승인 완료를 만들지 못함 | 미실행 |
| RT-P07 | 선행 대기·독립 분기·Step 표시 | 준비 상태가 실제 관계와 일치. 독립 분기를 불필요하게 전체 대기시키지 않음 | 미실행 |
| RT-P08 | 적용 제외·적용 조건 미확인·대상 0개 | 미확인은 제외가 아님. 대상 0개는 전체 PASS가 아님. 제외된 출력의 필요성 검사 | 미실행 |
| RT-P09 | 입력 수정·실패 재시도·늦은 이전 응답 | 현재 근거 무효화와 이전 시도 보존, 새 결과를 오래된 응답이 덮지 않음 | 미실행 |
| RT-P10 | UI 재클릭·AI 동일 요청·실행 중 서비스 중단 | 시도 중복 방지, 미확인 결과를 성공/무조건 재실행으로 처리하지 않음 | 미실행 |
| RT-P11 | 새 정의 게시·자산 버전 변경·권한 철회 | 기존 건의 정의/이력 보존, 현재 권한 적용, 바뀐 검증기로 조용히 판정하지 않음 | 미실행 |
| RT-P12 | P/T 집계 및 최종 담당자 확인 | 절차 완료와 상위 Outcome 검증을 구분. 근거 없는 상위 PASS 표시 없음 | 미실행 |
| RT-P13 | UI/AI의 동일 업무 조작·역할 제한 | 같은 Action·revision·권한·결과. AI가 게시/승인 권한을 우회하지 못함 | 미실행 |
| RT-P14 | Git 밖 사용자 자산·구버전 rule/의존관계·이전 이력 | 삭제·재등록·초기화·의미를 바꾸는 자동 변환 없음. 프로그램 원복과 데이터 복원을 구분 | 미실행 |
| RT-P15 | 실제 담당자의 대표 업무 완료 및 원문 대조 | 설명 없이 시작/입력 보완/오류 대응 가능. 기준선 대비 시간·품질은 실측 범위만 기록 | 미실행 |

RT-P07은 순서상 준비 계산을 확인하며 실제 동시 실행의 통과 판정이 아니다. 실제 병렬 실행을 추가하면 공유 자원·권한·동시 실행 한도·결과 순서의 별도 사례를 추가한다. 한 업무 통과를 범용 Runtime·팀 공동 Case·모든 사용자 격리 검증으로 확대하지 않는다.

## 2. 결과 기록 단위

시험마다 날짜, 코드/정의/검증기 버전, 환경, 입력 사례 식별자, 수행 경로(UI/AI), 기대 결과·관측 결과, 판정, 근거 참조, 미확인을 기록한다. 실제 식별자·대화 원문·PAT·내부 응답은 이 저장소에 복사하지 않는다. 합성 오류 시험과 실제 내부 도구 실행을 각각 표시한다.

## 3. 실환경 대표 업무 선정 전 확인

대표 P와 첫 실제 J, 승인된 도구와 현재 사용자 권한, 요청/응답·정상/이상/불완전 사례, 판정 명세, 사람 확인 범위를 확정한다. Confluence/Jira/GitHub 또는 승인 진단 API 중 업무에 필요한 기존 연결을 우선한다. DB/AP 실행 경로가 준비되었다고 가정하지 않는다.
