## 검사와 실패 기록

### 환경과 준비 차단

이번 실행 가능 환경은 Python3.12.14 / Node24.19.0이다. 저장소가 요구하는 이전 Python3.11 실행파일과 고정 Open WebUI upstream wheel,Chrome/Chromium 실행파일은 현재 scratch에 없다. 이 세션에서 공식 Native 앱·브라우저를 실행했다고 주장하지 않는다. 과거 GitHub run7개의 artifact 목록은 비어 있었고,PyPI 직접 접근도 제한 시간 초과로 중단했다. 동일 실패를 긴 대기/반복 다운로드나 사내 환경 변경으로 우회하지 않았다.

누락 FastAPI 등 순수 Python 의존성은 기존 보존된 pure dependency 경로를 뒤쪽에 추가해 관련 서비스 검사를 실행했다. Native `.so`나 브라우저를 mock으로 대체해 제품 검증으로 계산하지 않았다. 정확한 명령/환경·개별 결과는 아래 최종 동결 검사 기록으로 확정한다.

### 구현 중 실패와 보완

- 초기 panel46 검사에서22 failure가 나왔다. 일부는 의도된 C6행 페이지→V4 상태 묶음/접힘/행동2개/상단·하단 복귀와 테스트 DOM `aside`→제품 `main` 차이였다. 해당 기대만 V4 계약으로 갱신하고 저장/이력/권한 assertion은 유지했다.
- 실제 누락이었던 초기 상세 설명·조회 이후 무효 결과 표시·역사 기록의 current select 노출·실패 결과의 우선 표시를 수정했다. 초안 변경/선행 재실행 이후 이전 성공이 현재 결과로 돌아오지 않는 검사를 유지했다.
- 초기 Native execution UI25 중3 failure는 UNKNOWN의 새 표기,inline 공개 schema 저장 경로,그 표기를 포함한 P/T 테스트 기대였다. UNKNOWN의 자동 실행0,모든 허용/금지 제어·부분 결과·snapshot·ACL 검사 자체는 보존했다.
- malformed JSON 초안,raw 값/필드 오류의 화면 복귀,preview→case receipt/버전 이동,document keydown 분기,select 초점과 과거 참고 label을 추가 보완했다. 사용자가 명시적으로 초안을 버릴 때는 typed 초안뿐 아니라 raw 값/오류/AI receipt를 함께 지우고 버전을 바꾸며 저장값은 보존한다. 조회 실패로 초안을 임의 폐기하는 동작과 구분한다. 이 내용은 순수 view/controller/서비스 검사이며 실제 Native IME나 브라우저 결과가 아니다.

### 막혔던 Native 업무·대화 통합 검사의 첫 관측

기존 CI의 step33은 CSS 검사 실패로 미실행이었다. 기존5개 파일73개 중 failfast로 첫 시험을 실행하여 동일 실패를 전체에 반복하지 않았다. `test_ees_work_demo.py`의 종료 전 cleanup에 PNG·허용된 DOM/readiness·마지막 wait/click·요청 method/path 수집을 보완했다. setup/teardown/SubTest 실패도 브라우저 종료 전에 기록하며 입력값·token·cookie·storage·인증 body는 남기지 않는다.

첫 시각 시험1개는10.304초에 연결 문구 대기 실패였다. 실제 Native는 ready였으나 업무 패널이 닫혀 있었고, 코드상 연결 문구는 패널이 열릴 때만 생성된다. 실제 패널 열기 버튼을 누르는 준비 helper를 추가한 해당1개 재검에서는 이 준비가드를 통과했지만2.119초에 기존 A안의 대화 폭420px 이상 기대가 현재 V4의359px와 달라 실패했다. 현재 source는 기본 Assistant360px·업무 패널이 대화 왼쪽·제목24px이며 구 시험의 A안 배치/규격과 다르다. 이 시각 기대를 임의 완화하거나 제품 배치를 바꾸지 않는다.

이어 이미 완료한 시각 실패를 다시 실행하지 않고 기능 대표4개를 failfast로 선택했다. C3 동일 계정 두 탭의 revision 충돌/미저장 입력·서버 결과 보존은 PASS였다. 다음 대화/패널 동일 진행 건 시험은 물리 전송·등록 도구 호출·실제 DB 결과 저장 assertion을 통과한 뒤 옛 완료 문구 대기에서 실패했다(2개15.186초,1PASS/1FAIL). 현재 view의 simulation 분기는 모의 점검 통과와 실제 업무 완료 미확인을 구분하므로 테스트의 문구 기대만 그 의미에 맞춰 보완한다. 실패 때문에 아직 실행되지 않은 C1/C2는 통과로 표시하지 않는다. 각각의 원래 상태·저장·권한 검사는 유지한다.

후속 C1/C2도 reload 뒤 닫힌 패널을 기다리는 같은 helper 경로임을 실패 화면으로 확인했다. 공통 실제 토글을 사용하고 삭제된 경로/열기 컨트롤을 현재 breadcrumb/토글로 연결했다. 완료·모의 통과·제외 그룹의 기본 접힘도 기존 표시 버튼을 실제 클릭해 해제하며 DOM 상태를 직접 바꾸지 않았다. 모의 결과 문구는 `모의 점검을 통과했습니다. 실제 업무 완료는 확인하지 않았습니다.`로 정확히 검사하고 옛 완료 확정 문구가 없는지도 검사한다. 저장/도구/진행 건/과거 결과 assertion은 유지한다.
