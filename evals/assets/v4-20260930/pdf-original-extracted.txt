EESWork UI 구현 인계서 v4
Sep 30, 2026 · @테잘
0. 이 문서의 사용법
구현 기준은 Figma 페이지 “Opus 제안 · EES Work 09.30” 맨 위의 4차 두 화면과 이 문서뿐입니다. 둘
이 다르면 동작 규칙은 이 문서를, 시각 치수는 Figma를 따릅니다.
기준으로 쓸 것: 프레임 “4차 · A · 작업 목록”, “4차 · B · 작업 상세”, 변수 컨렉션 EES Work v4 /
Color , 텍스트 스타일 EES v4/* , 컴포넌트 Status glyph v4 , Button v4 , Icon/* .
무시할 것: 같은 페이지의 1·2·3차 프레임, 다른 페이지(F1.2, E안, 탐색안 등)의 시각 표현, v4가 아닌
변수 컨렉션( EES Opus / Color , EES Work v3 / Color , EES v2 / * 등), 이름에 v4가 없
는 Button·Status·Badge 컴포넌트.
판단 우선순위: ① 제품 제약과 동작 규칙(7·8장) ② 이 문서의 토큰과 치수(3·4장) ③ Figma 픽셀.
합성 데이터: 화면의 사람 이름, 작업 번호(SI-DB-01), 시각, 코드(HTTP 503), 집계는 모두 예시입니
다. 코드에 하드코딩하지 말고 데이터에서 받아 표시합니다.
빈곳을 채우지 말 것: 10장의 미결정·미설계 항목은 임의로 디자인하지 않습니다. 기존 컴포넌트로 최
소한의 자리만 만들고 TODO(인계서 10장) 주석을 남깁니다.
1. 제품 맥락
EES Work는 제조 현장 설비 시스템 조직이 셋업·운영·장애대응 업무를 절차대로 수행하도록 돕는
Open WebUI 기반 사내 업무 도구입니다. 가장 중요한 기준은 AI와 시스템을 모르는 비개발자도 처음
본 화면에서 “지금 할 일과 다음 행동”을 찾을 수 있는 것입니다.
업무 구조(화면 용어 · 코드 용어):
작업 공간 = 공장 + 시스템 (예: 천안 공장 · EMS)
업무 분류: 셋업 / 운영 / 장애대응
워크플로우 · P (예: 신규 공장 횡전개)
단계 · T (예: 3 시스템 설치)
작업 · J (예: 3.02 DB 연결 확인)
디자인 원칙:
업무가 화면의 중심이고, EES Assistant는 오른쪽에 항상 보이는 보조 영역입니다.
직접 조작과 대화는 같은 대상·상태·권한·업무 기능을 씁니다. 대화로만 가능한 일은 만들지 않습니다.
시스템다운 절제: 평평한 면, 1px 구분선, 구체적인 데이터, 명사형과 “~합니다”체 문구. 그림자, 그라
데이션, 알약형 태그 남발, 보라색 AI 연출은 쓰지 않습니다.
도구·스킬·모델, P/T/J 같은 기술 용어는 기본 흐름에서 숨기고 “기술 정보” 안에 둡니다.

6. 화면별 명세
사이드바 (두 화면 공통)
위에서부터: 제품명 행(22px 로고 + “EES Work” + 접기 버튼) → 작업 공간 선택(공장 표식 28px + “천
안 공장” / “EMS” + 펼침 표시) → 메뉴(내 업무 · 워크플로우 찾기 · 실행 기록 · 대화 기록) → 구분선 →
“업무” 트리 → 빈 공간 → 계정 행(이름 + 직무 + 설정).
트리는 셋업·운영·장애대응 세 분류를 최상위로 두고, 그 아래 진행 중인 워크플로우, 펼친 워크플로우
아래 단계를 보여줍니다.
분류 옆 숫자는 진행 중인 워크플로우 수이고, 장애대응에 진행 중인 건이 있으면 빨간 점(6px)을 붙
입니다.
워크플로우 옆에는 완료/전체 작업 수(73/120), 단계 옆에는 상태 기호와 완료/전체(25/48)를 표시
합니다.
A · 작업 목록 (단계 화면)
1. 상단 바: 경로 “셋업 / 신규 공장 횡전개 / 시스템 설치”(마지막만 Body Medium), 오른쪽에 “절차 보
기”와 더보기.
2. 페이지 머리: “단계 3 / 4”(Label) → 제목(Title L). 제목 오른쪽에 진행 막대(160×4,
brand/muted)와 “25 / 48 완료”. 아래 한 줄: 단계 설명 · 일정 · 담당 n명 · 절차 버전.
3. 도구 막대: 검색(260×32, “작업 이름으로 검색”) · 담당 필터 · 정렬(기본 “권장 순서”, 그 외 절차 순서
·최근 실행) · 오른쪽 끝에 “48개 작업”.

허용하지 않습니다.
공용 비밀키나 승인 없는 자동 실행을 전제하지 않습니다.

수락 기준은 세 가지 질문입니다. 처음 쓰는 사람이 추가 설명 없이 현재 업무·상태·다음 행동을 찾는가. 대
화와 업무의 대상이 혼동되지 않고 질문 없이도 직접 수행할 수 있는가. 작성·저장·실행·판정·과거 기록이
구분되는가.
검증 결과는 종류를 나눠 보고합니다. 코드·화면 자체 점검, 디자이너 검토, 실제 사용자 검토, 제품 동작
검증은 서로 다른 것이며, 하지 않은 검증을 한 것처럼 쓰거나 효과 수치를 만들지 않습니다.
