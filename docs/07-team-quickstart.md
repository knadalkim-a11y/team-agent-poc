# EES Workflow 처음 사용하기

C18 메뉴와 첫 사내 업무 진행을 위한 사용 안내입니다. 실제 설치본의 적용 여부와 검증 결과는 [현재 상태](STATUS.md)를 먼저 확인하세요. 새 기본 상태에는 데모 절차·전문 Assistant·사전 등록 스킬·시연 질문이 없습니다. 기존 개인 계정·대화·첨부·모델 연결과 개인 도구 설정은 유지합니다.

<a id="system-authoring-20260924"></a>

## 로그인과 첫 화면

1. 전달받은 기존 Native 로그인 화면에서 본인 계정으로 로그인합니다. 가입이 열려 있으면 가입을 신청하고, **계정 활성화 대기** 상태라면 담당자의 신원 확인·일반 사용자 승인을 기다립니다.
2. 왼쪽은 작업 위치·탐색, 가운데는 기존 대화, 오른쪽은 업무 패널 또는 절차 작성기입니다. 업무 작성 또는 Open WebUI 워크스페이스 권한이 있으면 **업무 / 워크스페이스** 전환도 보입니다. 공장·시스템 칸을 누르면 바로 아래 목록이 열리며, 워크스페이스에서는 관리 시스템만 고릅니다. 공장이8개 이상이면 검색할 수 있고 권한이 없는 항목은 흐린 ‘권한 없음’으로 표시되어 선택할 수 없습니다. Enter·Space로 열고 방향키·Enter로 선택하며 Esc로 닫으면 칸으로 돌아갑니다. 다른 시스템을 고르면 공장 선택은 해제됩니다. 범위를 바꾸어도 개인 대화와 현재 세션의 작성 중인 글·펼침은 유지됩니다.
3. 대화에서는 본인에게 허용된 Native 모델을 사용합니다. 특정 EES Assistant 프리셋을 선택할 필요가 없습니다. 모델 연결이 없어도 권한 있는 직접 작성·저장은 가능합니다. AI 기능은 사용할 모델과 연결이 필요합니다.
4. 업무 목록이 비어 있으면 아직 게시한 절차가 없는 상태입니다. 일반 사용자 승인과 절차 작성·실행 권한은 별개입니다. 담당자에게 필요한 업무 범위를 문의하세요.

비밀번호를 잊으면 운영 담당자에게 기존 관리자 재설정을 요청하세요. 비밀번호·토큰은 채팅에 보내지 않습니다. 개인 서비스 연결은 사용할 기능에만 필요하며 가입할 때 모든 PAT를 준비할 필요는 없습니다. 계정·그룹·세션 운영은 [Native 운영 가이드](03-openwebui-native-agent.md#system-authoring-20260924)를 따릅니다.

워크스페이스의 **업무 만들기**에는 업무 절차·도구·스킬·지침이, **AI 설정**에는 AI 도우미·참고 문서·빠른 문장이 권한에 따라 나타납니다. 현재 스킬·AI 설정은 원래 Open WebUI 화면을 왼쪽 EES 메뉴와 함께 엽니다. 왼쪽 업무 절차·도구를 누르면 같은 세션의 원래 대화와 작성 중인 내용으로 돌아옵니다. 새로고침하거나 로그아웃하면 메모리의 복귀 정보는 사라집니다. 관리자에게는 기능 연결·공장·접근 범위·관리자 설정도 보입니다. 관리자 설정 창이 열렸을 때는 원래 닫기 버튼이나 Esc로 먼저 닫습니다. [자세한 메뉴 안내](03-openwebui-native-agent.md#menu-integration-20261006)를 참고하세요.

AI 설정이 보이지 않으면 관리자에게 그룹 권한(모델·지식·프롬프트·스킬)을 요청하세요.

새 절차를 열면 가운데 대화에 **업무 도우미** 안내가 나타납니다. 질문이나 도움말의 **대화창에서 더 묻기**를 누르면 바로 보내고 답하며, 쓰던 글과 첨부는 그대로 남습니다. 질문 옆 **참고**에는 질문할 때 보고 있던 화면이 표시됩니다. 답변 중에는 버튼이 잠시 꺼지고, 도우미를 사용할 수 없으면 보내지 않고 안내합니다. 지금은 만드는 방법을 설명하며 말로 절차 초안을 만드는 기능은 제공하지 않습니다. 이2단계 후보의 실제 적용 여부는 위 현재 상태에서 확인하세요.

## 첫 사내 업무 한 건 끝내기

업무 내용은 사용자가 사내에서 고릅니다. 이미 연결된 읽기 기능 하나로 자료를 조회하고, AI 초안을 사람이 확인해 끝나는 **수시** 절차를 만듭니다. 이번에는 스킬·예약·자동 실행·EES 요청을 사용하지 않습니다. 프로그램 적용은 [사내 적용 안내](03-openwebui-native-agent.md#source-frontend-apply-20261013)를 따르고, 아래 흐름의 결과는 [통합 확인 목록](03-openwebui-native-agent.md#internal-pilot-checks-20261012)에 한 번만 남깁니다.

1. **관리자 연결 준비:** **워크스페이스 → 공장·접근 범위 → Work 도구 설정 확인**에서 제품 원본·허용 함수를 확인합니다. 미등록이면 사용할 팀원 또는 Native 그룹의 읽기·제안 권한을 선택해 **확인한 원본 등록**을 누릅니다. 이미 연결되어 있으면 원본과 권한을 유지하므로, 팀원에게 기존 `ees_workflow` 읽기 권한이 있는지 Native에서 확인합니다. 원본 검토가 필요하다는 안내가 나오면 강제로 덮어쓰지 않습니다.
2. **팀원 준비:** 같은 화면의 **접근 범위 등록**에서 업무의 시스템·공장에 팀원 또는 소속 그룹의 **참여·실행**을 설정합니다. 조회 권한만으로는 작업을 끝낼 수 없습니다. 별도로 사용할 Native 읽기 도구와 기반 모델의 읽기·사용 권한을 확인하고, 팀원은 [본인 개인 설정](#내-계정-연결하기)의 PAT와 원 시스템 접근 권한을 사용합니다. 업무 참여를 위해 Native 자산의 코드 편집 권한까지 줄 필요는 없습니다.
3. **읽기 도구 준비:** 관리자가 해당 시스템의 **도구 → 새 도구 → 연결된 기능에서 고르기**에서 실제 Jira·Confluence·GitHub 기능 하나를 고릅니다. **정보 읽기**로 표시된 기능을 선택하고 이름·조회 목적을 적어 **초안 저장 → 확인 요청 보내기 → 담당 확인**을 진행합니다. 최초 실행 허용을 요구하면 관리자가 정확한 코드·시험·환경의 검토 근거를 8자 이상 남깁니다. 예시 형식은 `EES Jira Read / jira_get_issue / YYYY-MM-DD / 사내 본인 계정으로 이슈 조회 성공 확인`입니다. 직접 시험한 도구명·함수·날짜·결과로 바꾸고 비밀값·사내 주소는 넣지 않습니다. 이미 허용된 읽기 기능은 시스템 담당자가 확인할 수 있습니다. Native에 등록되어 있다는 이유만으로 모든 함수가 정보 읽기 대상이 되지는 않습니다.
4. **절차 작성·게시:** **업무 절차 → 새 절차 → 빈 절차로 시작**에서 이름을 입력해 **초안 만들기**를 누릅니다. 단계 하나에 아래 세 작업을 추가하고, 수행 안내·필수 입력과 실제 도구 인자의 연결을 작성합니다. 작업 담당자는 수행할 팀원 또는 소속 그룹으로 정합니다. **실행 후 사람이 확인해야 완료**를 유지하고 스킬은 연결하지 않습니다.

| 작업 | 수행 방식 | 결과 형태와 연결 |
|---|---|---|
| 사내 자료 조회 | 도구 실행 | 사람 확인 · 위에서 확인 완료한 도구 선택 |
| 조회 결과의 초안 작성 | AI 초안 | AI 초안 검토 · 선행 작업은 자료 조회 · 완료 조건은 **초안 검토 완료** |
| 최종 업무 확인 | 사람 확인 | 사람 확인 · 선행 작업은 초안 작성 |

**절차 설정**에서 실행 방식 **수시**와 실제 수행 범위를 확인한 뒤 **초안 저장 → 게시 전 확인 → 게시**합니다. AI 수행 안내에는 조회한 근거로 작성할 내용과 사람이 확인할 사항을 적습니다. 선행 작업의 현재 결과와 사람 판정이 AI에 전달됩니다. 도구 입력은 함수의 실제 정의에 맞춰 연결하며 자동으로 채워졌다고 가정하지 않습니다.

5. **비관리 팀원이 완료:** 본인 계정으로 **업무 → 해당 절차 → 진행 건 시작**을 누릅니다. 조회 입력을 저장하고 첫 작업의 **지금 실행**을 누른 뒤 결과와 실행 기록의 근거를 확인해 **판정 확정**합니다. 두 번째 작업에서 사용할 모델을 확인하고 **지금 실행**을 누릅니다. 초안을 읽고 보완한 뒤 자동 저장 상태를 확인해 **판정 확정**합니다. 마지막 작업의 **확인 완료** 후 개요에서 **진행 건 종료**까지 확인합니다. 관리자가 대신 완료한 결과로 팀원 확인을 대신하지 않습니다.

팀원이 직접 시작한 진행 건은 그룹을 선택하지 않으면 개인 진행 건입니다. 관리자가 시작한 건을 함께 처리하려면 시작할 때 팀원이 속한 Native 그룹도 참여 그룹으로 지정해야 합니다. 개인 대화는 공유되지 않습니다.

**현재 제한:** AI 초안의 완료 조건을 **실제 송부 완료**로 정하면 송부 연결이 없어 종료가 막힙니다. EES 요청 기능도 연결되어 있지 않습니다. 게시 절차가 사용하는 스킬을 바꾸면 자동·직접 실행과 이전 게시 버전의 새 회차가 막히며, 이미 열린 회차의 해당 작업을 정상 완료할 방법은 아직 없습니다. 새 지침은 다시 검사·게시하고 새 버전으로 바꾼 뒤 여는 회차부터 사용할 수 있습니다. 이번 업무는 스킬을 연결하지 않고 진행합니다. 실패·부분 결과·모델 오류를 완료로 처리하지 말고 통합 확인 목록에 화면 문구를 남기세요.

## 절차 작성·저장·게시

1. 권한 있는 시스템 담당자는 **워크스페이스**에서 관리 시스템을 선택하고 **업무 절차**에서 새 절차를 만듭니다. 절차 아래 단계와 작업을 추가하고 수행 안내·입력·결과 형태·선행 작업을 작성합니다.
2. AI에 초안을 요청하면 제안을 먼저 검토합니다. **편집 초안에 반영**은 편집 중인 글을 바꾸는 행동이며 서버 저장·게시·실행이 아닙니다. 실제 입력이나 판정도 AI 제안만으로 확정되지 않습니다.
3. **초안 저장 → 게시 전 확인 → 게시**를 진행합니다. 미완성 입력·순환 선행조건·변경된 Native 도구 참조 등은 게시 검사에서 확인합니다. 도구나 스킬을 연결하지 않은 사람 확인 작업도 작성할 수 있습니다.
4. 게시 버전은 보존됩니다. 새 진행 건을 시작할 때 버전을 선택하며, 이후 초안을 수정해도 이미 시작한 건의 절차가 바뀌지 않습니다. 버전 기록에서 당시 정의를 확인할 수 있습니다.

다른 담당자가 먼저 저장했다면 미저장 글을 유지한 채 최신 저장본과 비교하세요. 자동으로 덮어쓰거나 새 revision으로 바꾸지 않습니다. 로그아웃·다른 계정 전환은 개인 편집 캐시를 정리하므로 필요한 글을 먼저 저장하세요.

**판정 규칙**에서는 작업을 선택해 판정 단어·상태·후속 의미와 AI 제안 지침을 정합니다. AI 제안 지침은 자동 확정 규칙이 아닙니다. **게시 전 확인**은 게시를 막는 문제·확인 권장·통과를 나눠 보여 줍니다. 송부 방식과 D-5 이후 미승인 CR 처리 미정은 확인 권장으로 남겨 게시할 수 있으며, 실제 보내기·처리는 해당 조건을 확인할 때까지 막힙니다.

업무 설정은 반복 사용하는 값이고 이번 진행 건 입력과 별개입니다. 기본값과 공장별 지정값을 구분하며, 공장별 값 미지정은 빈 문자열·0·아니오와 다릅니다. 프로젝트·상태 같은 선택지는 현재 권한으로 실제 도구에서 가져올 수 있습니다. 필드 ID·도구 인자 연결은 작성자가 정의하며 비밀정보를 입력 항목으로 만들지 않습니다.

## 진행 건 시작과 작업

1. **업무**에서 공장·시스템과 게시한 절차를 선택하고 **진행 건 시작**을 누릅니다. 게시 버전과 참여할 Native 그룹을 확인합니다. 그룹을 선택하지 않으면 개인 진행 건이며, 개인 대화를 공동 업무 내용으로 복사하지 않습니다.
2. 작업의 **이번 진행 건 입력** 또는 **업무 설정**을 확인하고 저장합니다. 입력 저장과 **지금 실행**은 별도 행동입니다. 페이지를 열거나 질문하는 것만으로 진행 건·실행을 만들지 않습니다.
3. 도구 결과의 조회 범위·부분 결과·근거를 읽고 필요한 항목을 직접 판정합니다. 도구 성공과 업무 완료는 다릅니다. AI 제안은 실제 모델명이 붙은 제안으로 표시되며 사람이 확인하기 전 완료되지 않습니다.
4. 보완 후 같은 진행 건에서 다시 실행할 수 있습니다. 이전 입력·결과·판정은 실행 시도별로 남으며, 바뀐 근거에 의존한 후속 작업은 재확인이 필요합니다.

**내 업무**에서 입력·확인·재점검할 작업을 열 수 있습니다. 예약은 게시 버전·시간대·실행 계정·위임 범위를 지정해 서버에 저장합니다. 브라우저를 닫아도 접수된 실행이나 예약이 멈춘다고 가정하지 마세요. 지연·재기동·권한 변경으로 실행되지 않은 회차는 기록을 먼저 확인합니다. 비상 실행도 사람 확인·권한·EES 요청 승인 조건을 생략하지 않습니다.

수시 업무는 진행 건 목록에서 이어 하거나 **새로 시작**합니다. 공장 단위 업무는 이미 같은 업무가 진행 중인 공장을 다시 시작할 수 없습니다. 시스템 단위 업무는 공장을 바꿔도 같은 진행 건을 보여 줍니다. 주기 업무의 다음 회차는 직전 회차의 미완료 여부와 별개로 예정 시각에 열립니다.

항목별 판정은 선택 내용을 자동 저장한 뒤 **판정 확정**으로 최종 반영합니다. 저장 중·저장 실패 안내를 확인하세요. AI 제안만으로 선택하거나 확정하지 않습니다. 검토 초안은 자동 저장되므로 별도 저장 버튼이 없으며, 자동 저장 실패 시 작성한 내용을 유지합니다. 검토 완료가 실제 송부 완료를 뜻하지는 않습니다.

업무 패널 경계를 끌거나 키보드 방향키로 너비를 조절할 수 있으며 본인 계정에 저장됩니다. 좁은 화면에서는 사이드바를 아이콘 막대로 접고, 기본 패널을 함께 놓을 공간이 부족하면 패널이 대화 위에 열립니다. 패널을 넓혀서만 대화 폭이 부족해지는 처리 방식은 아직 확인 필요입니다.

## 결과와 기록

작업의 **실행 기록**에서 당시 입력·도구 참조·결과·사람 판정을 확인합니다. **기록 JSON 내보내기 / 기록 텍스트 내보내기**는 현재 권한으로 서버에서 다시 확인한 자료를 내보냅니다. 권한을 잃은 원본 근거는 이전 화면 캐시로 대신 제공하지 않습니다. 결과 초안은 검토·저장·내보내기와 실제 송부를 구분합니다.

미승인·판단 불가·부분·실패·결과 불명은 성공으로 합치지 않습니다. 모든 필수 완료 조건을 충족하지 못하면 진행 건 종료가 차단됩니다. 종료된 진행 건과 이전 버전 기록은 읽기 전용으로 확인하며, 과거 데모의 실행 기능을 되살리거나 이력을 자동 삭제하지 않습니다.

## 실제 조회 도구와 배포 자료 점검

Jira·GitHub·Confluence 조회는 기존 Native 도구의 권한과 본인의 개인 설정을 사용합니다. **워크스페이스 → 도구**에서 담당자가 현재 함수·입력 계약·확인 자료를 등록하고 검토합니다. 도구 이름을 등록하는 것만으로 자동 실행이 허용되지는 않습니다. 기존 Native 모델·도구·스킬 관리는 각자의 Native 권한으로 엽니다.

배포 자료 점검 절차는 사용자가 작성·게시한 뒤 사용합니다. Jira에서 실제 프로젝트·상태·날짜 필드를 선택하고 CR 목록을 조회·확정합니다. 시스템 이름을 프로젝트 키로 추정하지 않습니다. 필수 첨부는 사용자가 지정한 정확한 파일 이름으로 존재·접근 여부를 확인합니다. **첨부가 있거나 읽을 수 있다는 결과는 내용 적정성 승인이 아닙니다.** 불명확하거나 미검토인 내용은 판단 불가로 남깁니다. [Jira 조회 계약](05-jira-read-tool.md)

목록이 일부만 조회되거나 CR이 누락되면 완전한 확정 목록으로 다음 배치 조회를 실행할 수 없습니다. 목록을 수정·제외·재조회하면 변경 이유와 새 근거를 남기고 후속 판정을 다시 확인합니다. 결과 보고 초안은 미승인 CR의 판정을 그대로 보존할 수 있지만 배포 포함/제외를 자동 결정하지 않습니다.

EES 변경 요청은 등록 계약·담당자 확인·사용자 최종 확인·접수/상태/효과 확인을 분리합니다. 실제 EES 연결이나 송부 채널이 구성되지 않은 행동은 이유를 표시하고 차단합니다. 확인되지 않은 성공 응답이나 운영 DB 직접 조작으로 대신하지 않습니다. 영업일 계산에 필요한 공휴일 달력이 없으면 확인 불가로 표시하며 임의로 날짜를 앞당기지 않습니다.

EES 요청 값은 등록된 도구의 입력 정의와 같은 형식으로 작성합니다. **요청 사유**는 요청 기록과 최종 확인에 따로 남으며 도구의 입력값에 임의로 추가하지 않습니다. **직접 실행 · 예외**는 API 제공이 어려운 사유와 EES 담당자·허용 명령·최소 권한 계정·효과 확인 조건을 검토하는 등록 유형입니다. 등록·검토만으로 실행기가 연결되지는 않으며 실제 연결이 없으면 요청·상태 확인을 차단합니다.

## 내 계정 연결하기

문서·이슈·PR 조회에는 사용할 서비스의 본인 개인 토큰(PAT)이 필요합니다. 이미 등록한 값은 다시 입력하지 않습니다. Native 대화의 **통합 → 도구 → 해당 항목 옆 개인 설정(밸브)**에서 입력하고 저장합니다. 화면에 따라 Controls의 도구 Valves로 표시될 수 있습니다.

| 사용할 서비스 | 기존 개인 설정 항목 |
|---|---|
| Jira | EES Jira Read |
| Confluence | EES Confluence Read |
| GitHub | EES GitHub Read |

PAT는 업무 설정·진행 건 입력·보고서·채팅에 복사하지 않습니다. 항목이 보이지 않으면 해당 도구의 본인 접근 권한을 문의하세요. 관리자 공용 토큰으로 대체하지 않습니다.

## 막히면

인증 실패는 해당 서비스의 개인 설정을, 조회 제한은 실제 대상과 원 시스템의 본인 권한을 확인하세요. 선택지 조회 실패는 0개 선택지나 예시 값으로 대체하지 않습니다. 필요한 정보가 없거나 정책이 미정인 부분은 화면의 차단 이유를 확인합니다. 담당자에게 작업 종류·오류 문구·민감값 없는 기록 식별자를 알려주되 토큰·실제 업무 본문은 함께 보내지 마세요.
