# EES Work 처음 사용하기 — 팀 시연 준비본

팀 시연을 위한 안내입니다. 아래 업무는 현재 연결 기능의 예시이며 일반 질문·글쓰기·내용 정리에도 사용할 수 있습니다. 실제 첫 화면 적용과 안내 전달 여부는 담당자가 확인합니다.

EES Work의 전달받은 사내 주소에서 본인 계정으로 로그인하고, 새 대화에서 **EES Assistant**를 선택하세요. 기존 설정에 따라 **EES 통합 Assistant**로 보일 수 있습니다. 서비스 이름 변경으로 기존 모델 이름과 대화가 바뀌지는 않습니다. 원하는 일을 직접 적으면 됩니다.

<a id="system-authoring-20260924"></a>

## 가입과 첫 이용

1. 전달받은 기존 로그인 화면에서 본인 계정으로 로그인하세요. 가입이 열려 있으면 **가입**으로 신청합니다. 가입이 닫혀 있으면 운영 담당자에게 기존 계정 생성 절차를 문의하세요.
2. **계정 활성화 대기**라면 담당자의 신원 확인·일반 사용자 승인을 기다립니다. 이메일 형식이 맞다는 이유만으로 신원 확인이나 업무 담당 지정이 끝난 것은 아닙니다.
3. 승인 후 새 대화에서 접근 가능한 **EES Assistant**를 고르고 질문 한 번을 보내세요. 모델이 보이지 않거나 연결되지 않으면 이용 권한/연결을 문의합니다. 전체 관리자 역할이나 모델 편집 권한을 받을 필요는 없습니다.
4. 왼쪽에서 허용된 게시 워크플로우를 열어 설명을 읽고 필요한 입력 또는 본인의 확인을 기록합니다. 가입·승인만으로 업무 절차 작성 권한은 생기지 않습니다.

비밀번호를 잊으면 운영 담당자에게 기존 관리자 재설정을 요청하세요. 비밀번호·토큰은 채팅에 보내지 않습니다. 개인 Jira·Confluence·GitHub 연결은 실제 사용할 기능에만 필요하며 가입할 때 모든 PAT를 준비할 필요는 없습니다. 로그아웃·비밀번호 변경의 다른 기기 로그인에 대한 효과는 [운영 가이드](03-openwebui-native-agent.md#system-authoring-20260924)의 실제 검사 범위를 따릅니다.

## 시스템 담당자의 업무 절차 관리

이 기능은 담당 그룹이 지정된 일반 계정에 제공됩니다. 기존 메뉴의 **업무 절차**로 들어가며 직접 경로는 `/?ees=workflow`입니다. 기존 Workspace를 사용할 수 있는 계정은 그 안의 업무 절차 탭으로도 같은 작성기를 엽니다. 다른 모델·도구를 편집할 권한은 추가되지 않습니다. 실제 프로그램 반영과 검증 상태는 [현재 상태](STATUS.md)를 확인하세요.

1. **관리 시스템**과 **워크플로우**를 선택합니다. **워크플로우 추가**로 새로 작성하거나 **게시본에서 복사**를 사용합니다. 같은 시스템 담당자가 만든 절차도 함께 관리할 수 있습니다.
2. P 아래 단계(T)·작업(J)을 작성합니다. 도구·스킬은 본인이 접근 가능한 기존 목록에서 선택하며 등록만으로 실제 외부 실행이 연결되지는 않습니다.
3. 표시된 **P 이름**을 확인하고 **초안 저장 → 게시 전 확인 → 게시**를 진행합니다. T/J를 선택했어도 저장·검사·게시 대상은 그 항목이 속한 P 전체입니다. 다른 P의 미완성 내용은 게시하지 않습니다.
4. 새 게시본은 이후 새 진행 건에 적용됩니다. 이미 시작한 업무의 절차·입력·결과·이력은 유지됩니다. 다른 일반 사용자도 기존 A안 화면에서 허용된 새 게시본을 사용할 수 있습니다.

다른 담당자가 먼저 저장했다는 안내가 나오면 내 미저장 글과 최신 서버본을 구분해 확인하세요. 시스템/P 이동 때는 **현재 세션에 유지하고 이동·초안 저장 후 이동·미저장 변경 버리고 이동·취소** 중 원하는 행동을 선택합니다. 담당 변경을 확인하려면 **권한·목록 새로 확인**을 사용하세요. 담당 권한이 회수되면 새 저장/검사/게시를 할 수 없지만 현재 로그인 세션의 작성 중인 글은 보존합니다. 로그아웃/다른 계정 전환에서는 개인 초안과 권한 캐시를 정리하므로 전환 전에 필요한 내용을 처리하세요. 담당 해제는 일반 이용이나 계정 사용 중지와 별개입니다.

## 공장별 업무 이어가기

1. 왼쪽 사이드바에서 **작업 공장**과 **시스템**을 선택하세요.
2. **워크플로우** 아래 **셋업·운영·장애대응**을 고르고 워크플로우 → 단계 → 작업 순서로 이동하세요. 작업이 많으면 단계 화면에서 이름 검색·상태 필터·이전/다음 페이지를 사용하세요.
3. 선택하면 오른쪽 업무 패널에 목적·완료 조건·현재 상태·다음 행동이 표시됩니다. 조회와 질문만으로 진행 건이 만들어지지 않으며 첫 입력 반영이나 실행 때 시작합니다. 이미 진행 중인 건은 이어갑니다.
4. 가운데 AI에게 설명·입력 수정·점검을 요청하거나 오른쪽 작업 패널에서 진행하세요. 작업 선택만으로 점검이 실행되지는 않습니다.

왼쪽 단계별 진행표에는 완료·진행·실패·대기 상태가 표시됩니다. **적용 제외**는 해당 공장에 필요하지 않은 작업이며 완료 수에 포함하지 않습니다. 공장과 시스템을 전환할 때 화면에 표시된 대상을 확인하세요. 다른 실행을 이어가면 그 실행에 연결된 대화에서 계속합니다.

오른쪽 **실행 이력**에서는 이전 실행 결과를 읽을 수 있습니다. 지난 기록을 열어도 현재 대화와 단계별 진행 상태는 바뀌지 않습니다. **현재 작업**으로 돌아오면 진행하던 작업을 이어갑니다. 완료한 절차를 다시 수행할 때는 **새 실행 시작**으로 별도 기록을 남깁니다.

DB/AP 점검은 합성 자료로 진행하는 모의 점검입니다. 실제 공장 연결 결과가 아닙니다. 선행 작업이 남아 있으면 먼저 완료할 작업을 확인하고, 담당자 확인이 필요한 항목은 내용을 확인한 뒤 완료를 기록하세요.

전체 관리자와 시스템 담당자는 위 **업무 절차**에서 허용된 P의 단계·공장 조건·도구/지침 참조를 편집합니다. 저장·검사한 선택 P를 게시하면 새 실행부터 적용됩니다. 기존 모델·지식기반·프롬프트 메뉴는 각자의 Native 권한을 그대로 따릅니다.

## 통합 UX 베타에서 확인할 흐름

- 왼쪽 가로 분류에서 워크플로우를 선택하고 단계 이름을 누르세요. 선택 단계의 작업명·상태가 바로 보이며, 많은 작업은 **전체 N개 작업 보기**에서 검색/필터로 찾습니다. 워크플로우의 완료 수·조치 필요 수도 확인하세요. 선행 대기·사람 확인 대기·적용 제외는 성공이나 실패와 다릅니다.
- 작업의 입력을 바꾼 뒤 **입력 반영**과 별도 실행을 차례로 확인하세요. 완료 뒤 **다음 작업 열기**는 이동만 하며 자동으로 실행하지 않습니다. 실패 결과를 읽고 해당 작업에서 재시도하세요. 사람 확인은 본인이 내용을 확인한 뒤 완료 버튼을 눌러야 하며 AI가 대신 완료하지 않습니다.
- 질문과 작업 입력을 작성한 상태에서 다른 작업을 선택하고 패널을 닫았다가 다시 여세요. 원래 대상·입력·대화와 이전 결과가 유지되는지 확인하세요.
- 권한 있는 담당자는 수행 안내를 AI로 수정하고 전후를 비교한 뒤 초안 저장 → 게시 전 확인 → 게시를 진행하세요. 저장된 선택 P의 초안만 게시되며 이미 시작한 건의 절차·입력·이력은 유지됩니다. AI가 연결되지 않아도 수동 작성은 가능합니다.
- 기존 도구·개인 설정은 새 탭에서 확인하고 원래 작성 탭으로 돌아오세요. 개인 설정은 Native Controls → Valves(밸브)에서 도구를 선택합니다. 권한이나 도구에 따라 항목이 다를 수 있습니다. 주소·키는 작업 입력에 붙여넣지 않습니다.

**실행 연결 필요**는 도구가 등록돼 있어도 업무 패널에서 실행할 연결이 없다는 뜻입니다. 기존 대화의 도구·스킬 선택은 계속 사용할 수 있습니다. DB/AP 모의 점검, 외부 도구 직접 실행 미지원, 일정·공유 권한 후속 범위를 구분합니다. 이 안내는 베타 준비본이며 실제 사내 적용 여부는 [현재 상태](STATUS.md)를 확인하세요.

## 첫 화면에서 시연하기

대표 제안 세 개를 누르면 준비된 시연을 시작할 수 있습니다.

| 제안 | 확인할 내용 |
|---|---|
| 생산 손실 줄이기 | 조립 2라인의 개선 기회와 근거, 먼저 확인할 항목 |
| 점검 WO 초안 작성 | 천안 권취 설비를 찾아 소음 점검 초안을 채우고 직접 수정 |
| 회의 전 업무 현황 보기 | Jira 시스템별 이슈 수·GitHub 열린 PR·Confluence EMS 문서 요약과 원문 |

분석과 설비·WO는 각각 별도의 합성 자료를 사용하며 실제 설비 상태를 조회하거나 EMS에 WO를 발행하지 않습니다. 업무 현황은 본인 계정으로 연결된 Jira·GitHub·Confluence의 실제 읽기 결과를 사용합니다. GitHub 저장소가 여러 개면 대상을 선택하고, EMS 문서가 없으면 실제로 있는 주제로 이어서 요청하세요. 질문이 입력창에 채워지면 전송하여 시작하세요.

## 현재 연결 기능의 사용 예시

| 업무 | 이렇게 시작하세요 |
|---|---|
| 시스템별 Jira 이슈 비교 | “시스템별 Jira 이슈 현황 보여줘.” |
| Confluence 문서 찾기 | 찾을 주제나 문서 제목을 함께 적으세요. 결과에서 필요한 문서의 내용과 원문을 요청할 수 있습니다. |
| 사내 GitHub의 열린 PR 확인 | “연결된 GitHub 저장소의 열린 PR 목록을 보여줘”라고 요청하세요. 대상이 여러 개면 Assistant가 물어봅니다. 목록에서 PR 하나를 골라 본문 요약과 원문을 요청할 수 있습니다. |
| 업무 내용 정리 | 정리할 내용을 보내고 핵심 내용·해야 할 일 등 원하는 형식을 말하세요. |

대상이나 조건이 부족하면 Assistant가 물어봅니다. GitHub는 현재 PR 목록과 본문을 확인하며 코드 검토나 리뷰 승인 상태 조회는 지원하지 않습니다.

## 내 계정 연결하기

문서·이슈·PR 조회에는 **사용할 서비스의 본인 개인 토큰(PAT)**이 필요합니다. 이미 등록했다면 다시 입력하지 않습니다. 업무 내용 정리에는 이 토큰이 필요하지 않습니다.

새 대화의 **통합 → 도구 → 해당 항목 옆 개인 설정(밸브)**을 열어 `PAT`에 입력하고 저장하세요.

| 사용할 서비스 | 개인 설정을 열 항목 |
|---|---|
| Jira | EES Jira Read |
| Confluence | EES Confluence Read |
| GitHub | EES GitHub Read |

토큰은 채팅에 붙여 넣거나 다른 사람과 공유하지 마세요. 설정 항목이 보이지 않거나 토큰이 없다면 담당자에게 해당 서비스 연결을 문의하세요.

## 조회 예시: 시스템별 이슈 현황

1. **“시스템별 Jira 이슈 현황 보여줘”**라고 요청합니다.
2. 답변의 전체·미완료 건수를 비교하고, 관심 있는 프로젝트 키를 넣어 **“이 프로젝트 이슈를 새로 조회해줘”**라고 요청합니다.
3. 목록의 이슈 키를 넣어 **“이 이슈의 상세 내용과 원문을 보여줘”**라고 요청하고, 원문 링크를 열어 Jira에서 확인합니다.

최근 이슈 목록은 조회한 일부 목록입니다. 다른 프로젝트나 다음 목록은 같은 대화에서 요청하세요. 저장된 대화는 당시 조회 결과이므로 최신 현황은 다시 질문합니다.

결과는 본인 계정으로 볼 수 있는 범위입니다. 조회 실패나 미확인 표시는 0건을 뜻하지 않습니다.

## 막히면

인증 실패는 해당 서비스의 개인 토큰을, 조회 제한은 요청 대상과 원 시스템의 본인 접근 권한을 확인하세요. 해결되지 않으면 **어떤 일을 하려 했는지와 오류 문구**를 담당자에게 알려주세요. 토큰이나 실제 업무 본문을 함께 보내지 마세요.
