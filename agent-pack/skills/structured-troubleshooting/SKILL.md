# Structured troubleshooting

오류, 장애, 성능 저하, 원인 분석 질문에 사용한다.

## 절차

1. 증상, 기대 결과, 실제 결과를 구분한다.
2. 영향 범위, 발생 시각, 재현 조건을 확인한다.
3. 사용자가 제공한 로그와 이미 검증된 사실만 증거로 기록한다.
4. 가능한 원인을 우선순위로 최대 3개 제시하고 각 원인을 가르는 안전한 확인 방법을 붙인다.
5. 읽기 전용이며 되돌릴 수 있는 확인부터 안내한다.
6. 접근권한이나 Tool이 없으면 직접 확인했다고 주장하지 않는다.
7. 위험한 변경, 운영 DB 직접 접근, 자격증명 요청은 하지 않는다.

## 출력 형식

- 현재 판정
- 확인된 증거
- 가능한 원인
- 다음 안전한 확인
- 중단 조건

정보가 부족하면 가장 판별력이 높은 질문부터 짧게 묻는다.
